## Executive bottom line

The LIVE face sells a coherent, honest product thesis — **fill forms, never submit; the bot that says no** — with a committed pixel-arcade system and repeated human-in-the-loop refusals. **It fails the honesty bar at the primary trust proof:** the face claims **open-source / public GitHub**, and the linked repo is **private (public visitors get HTTP 404)**. Until that is true or the claim is removed, DESIGN_AGENCY restraint and Rams honesty cannot clear. Secondary failures: hero supporting copy is a module laundry list (Hick), brand mark stays nav-scale while the headline owns the viewport, and arcade spectacle is the entire visual language (agency restraint FAIL). Soft leftovers are limited to the GitHub handle-in-URL; Soft pass stays REJECTED; Soft nav stays unpaid.

3. **Unobtrusive (5) / Understandable (4)** — Quiet the first viewport; define grill/veto in plain language at first use.

**Keep**

## Ranked fixes

Each item: severity · finding · acceptance criteria (AC). No Eng-build tip in this PR — AC only.

### Blockers

1. **Public GitHub / open-source claim vs 404**  
   - **Finding:** Hero tag “Open-source MCP server”, FAQ “this GitHub is public”, and Star/View GitHub CTAs point at a **private** repo that **404s** when logged out.  
   - **AC:** Either (a) `https://github.com/paulthorson/veto-mcp` returns 200 to a logged-out browser and matches the face, **or** (b) all visitor claims/CTAs that assert public open-source GitHub are removed or rewritten to match reality; no primary CTA dead-ends at GitHub 404.

2. **Honesty copy parity after (1)**  
   - **Finding:** “Free and open source” FAQ answer asserts public GitHub as proof.  
   - **AC:** Cost/open-source FAQ answer is re-verified against the live clone URL; no sentence claims a public GitHub the visitor cannot open.

### Concerns

3. **Hero Hick load**  
   - **Finding:** Supporting paragraph lists many modules before restating fill/submit.  
   - **AC:** First viewport supporting copy states boards + fill-never-submit (+ optional one clause); module inventory moves below fold; dual CTAs remain ≤2 with one primary job (install/try).

4. **Brand hierarchy (agency + brand test)**  
   - **Finding:** `VETO_` is nav-scale; headline owns the composition.  
   - **AC:** First viewport brand/wordmark reads as hero-level signal (size/placement/contrast) without adding badges/chips on the terminal; headline no longer fully displaces brand.

5. **DESIGN_AGENCY spectacle debt**  
   - **Finding:** Arcade spectacle is global; restraint FAIL.  
   - **AC:** No new spectacle layers; at least one subtraction pass on homepage chrome/motion/card density documented against DESIGN_AGENCY_BAR (restraint/hierarchy) without inventing metrics.

6. **Reduced-motion gap on hero terminal**  
   - **Finding:** Typewriter loop not observed to honor `prefers-reduced-motion` (CSS caret only).  
   - **AC:** Under `prefers-reduced-motion: reduce`, hero terminal shows a static final frame (or instant full text) with no continuous typewriter loop.

7. **Nav / module Hick**  
   - **Finding:** Long nav + engine + 17 playbooks.  
   - **AC:** First-visit IA exposes one primary path (install or demo) and groups modules so the first screenful of choices is materially smaller; Soft nav remains unpaid unless Soft-paid separately.

8. **WCAG Soft follow-through**  
   - **Finding:** Soft AA not cleared (faint-ink risk, small Read-more targets).  
   - **AC:** Soft AA Soft checklist pass on home + install + demo for contrast of text roles, 44px targets on primary actions/Read-more row, and focus visible — still Soft, still no Soft pass claimed until Soft-paid.

### Notes

9. **Glassdoor locked row**  
   - **Finding:** Locked board is honest; still adds Hick noise beside four live boards.  
   - **AC:** Locked stub either stays clearly unavailable without competing as a fifth “board you have,” or moves to limitations/boss-fights with equal-weight treatment per design system.

10. **Hash-router feature sprawl**  
    - **Finding:** Many `#/features/...` pages (including soft-skills module).  
    - **AC:** No new feature pages without a single homepage entry pattern; soft-skills remains product naming (not Soft scrub).

11. **Contact channel clarity**  
    - **Finding:** LIVE face uses `info@vetomcp.com` (no `hello@` on live bundle).  
    - **AC:** Single visitor contact remains consistent on privacy/disclaimer/footer; no second address introduced without Soft/Cos face rules.
